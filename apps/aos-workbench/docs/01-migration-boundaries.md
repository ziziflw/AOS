# 新旧工作台边界

P0-11 已复用相同布局与原有 Vue 控制层完成桌面集成。[当前入口与验收边界](../../../planning/p0-11-integration-report.md)。下表保留 React 预研阶段的职责记录。

预研范围采用 V3 的可操作工作台切片，V2 作为后续能力目录。新前端位于 `apps/aos-workbench`；从该目录的 npm 脚本启动独立入口。现有桌面程序继续使用 `demo/studio/frontend` 及其对应的 Rust 宿主。

|领域|本轮责任|真实系统的接入点|
|---|---|---|
|窗口布局|Dockview 处理面板、标签、分屏及拖动；工作区管理器负责布局版本、预设和恢复|布局属于视图偏好，独立于 C1|
|图草稿|在独立存储空间保存演示节点、连接、画布位置；图编辑器负责本地编辑和撤销|旧文档含 workflow 与 layout，未来导入须验证 typeId、版本、端口、catalogLock 和环境依赖，保留未知字段|
|检查器与目录|操作本地示例属性，节点类型说明与配色来自前端目录|真实节点 Schema 由 health 返回的 catalog 提供，运行版本由后端固定|
|运行及日志|用户可以查看演示模式和执行入口状态|宿主通过 host_request 承接 load、create、status、events、cancel，C1 提供事实快照|
|审批、连接与工具|隔离入口不启动执行进程，也不接触真实凭据与连接配置|原后端校验审批指纹与运行身份。模型选择、MCP、A2A 继续使用原实现|

## 联调边界

浏览器中的图对象、进程调用和持久化分别有不同的生命周期。接入真实后端时先验证便携 workflow 与 layout 的往返，再验证单个 runId 的状态与事件游标。错误须保留实际失败原因，历史画布草稿可以继续编辑。真实审批、凭据和未知副作用恢复由原执行器检查。

本次新工作区没有切换现有生产启动命令。回到旧界面直接使用原桌面启动器；保留新前端目录，即可继续访问同一浏览器来源下保存的演示布局和草稿。
