# P0-11 浅色集成工作台

从[启动入口](../START_HERE.md)打开真实窗口。中央画布连接 C1；左侧图标依次打开组件、文件、属性、模型、运行。单击同一图标可收起。右上角保存、校验、运行作用于当前草稿。

1. **新建或打开**。点「文件 → 新建工作流」，得到有文本输入、输出及有效连线的最小定义。点击列表中的文档名重新打开。打开示例会生成新的保存名称；文件面板可修改名称，支持 1–48 个英文字母、数字、下划线或短横线。相同名称保存会更新该工作区文档。
2. **添加、连线和参数**。从目录搜索、点选或拖入节点。拖节点可改变位置。拖输出端口至输入端口建立连接；也可双击节点，在左侧属性中点「从 out」，再双击目标节点点「连接到 in」。选中连线按 Delete 可移除。参数控件来自当前节点 Schema。双击文本输入编辑 value，按 Tab 提交，点击校验。未知节点可保存，其描述缺失时 C1 拒绝运行。
3. **模型**。先在 LM Studio 加载已有模型并启动本地服务。在「模型」选择 LM Studio 和实际回环地址（本次 127.0.0.1:1234/v1），点击「测试连接」、选择服务返回的模型 ID、点击「保存连接」。模板中的本地模型节点引用该绑定。模型列表、在线状态以本次查询为准。
4. **运行**。点击运行，左侧显示 runId、真实节点状态、输出和错误。展开「事件」查看事件序号。等待审批时查看动作输入，点击「批准本次操作」或「拒绝」。运行中可取消。编辑草稿不会替换已固定的运行定义。重新打开工作台会核实原运行，并在同一窗口配置中恢复该次运行的节点位置。缺少布局缓存的旧运行会自动排列。未知终态需要先核实已提交的操作。
5. **保存和交换**。右上「保存」或 Ctrl+S 写入本机 workspace。点「文件 → 导出 JSON」得到包含 workflow、layout 的文档，可通过「导入 JSON」载入其他草稿；单独的 workflow.json 不是该文件选择器的组合格式。标准示例直接从「文件」打开。[三个模板、依赖与预期输出](../examples/workflows/README.md)
6. **快捷键**。Ctrl+Enter 运行，Shift+F5 取消，Ctrl+Z / Ctrl+Shift+Z 撤销或重做，Ctrl+D 复制选中节点，Delete 删除，Home 适配画布。编辑参数时保留文字编辑按键。

# AOS 工作台使用手册

首次使用可直接点「使用离线示例 → 运行」。这个示例会实际启动自有 MCP Echo 工具，完成后在底部显示结果。使用 Ollama 或 LM Studio 需要另行配置连接。

## 从零创建文本工作流

1. 顶部点「新建」。在「节点库」搜索“输入与输出”，分别点击「文本输入」「文本输出」。节点以点击方式添加，按住节点标题拖动可以调整位置。
2. 点击输入节点，在右侧属性检查器修改 value 文本，按 Tab 提交。选中输出节点后再次选中输入节点可核对参数。
3. 将输入节点右侧 out 端口拖到输出节点左侧 in。也可在输入节点检查器的 out 行点「作为起点」，选中输出节点，在 in 行点「连接至此」。Text 只能连接兼容输入，类型不符会显示原因。
4. 点活动栏「工作流」，在「保存名称」输入 first-flow，修改顶部工作流标题后点「保存」。保存名称使用 1–48 个英文字母、数字、下划线或短横线；同名保存更新该文档。切换文档前先保存编辑。
5. 点击「运行」。底部「运行结果」显示输入的文本。点「打开」，在侧栏点击已保存名称，可恢复节点、边、参数和画布布局。「导出 JSON」可备份当前文档，另一台机器可从「工作流 → 导入 JSON」载入。

## 区域和操作

将鼠标停在左侧活动栏图标上查看名称。按从上到下的顺序，三个入口分别切换工作流、节点库、连接，再点当前入口收起。状态栏右侧的「属性」「输出」按钮分别控制检查器和运行面板。拖动面板边界调整大小，正常关闭后恢复布局。节点库使用可展开的分类树，支持名称、分类和用途搜索；「仅显示可添加节点」会隐藏缺少本地连接的节点。已保存连接仍需在运行时检查服务状态。

中间画布支持 Space 拖动平移、Ctrl 加滚轮缩放、「适应画布」显示整个图。点击节点或连线选择，Shift 多选。节点复杂参数在检查器中编辑。未知节点保留原始内容，可查看诊断。运行中修改的是当前草稿，已启动运行使用其固定版本。

本地模型：进入「连接」，选择服务、填写 127.0.0.1 回环地址，点「测试连接并获取模型」，选定模型后「保存连接」。回到节点库添加对应本地模型，将文本输入、模型和文本输出依次相连。服务和模型需由用户预先启动或加载。

运行错误查看底部「问题」，「事件」显示后端状态变化，「原始记录」提供详细诊断。「取消」向 C1 请求取消。已派发的外部操作可能返回未知，需核实实际结果。用量和合成估算以当前运行记录为准。

## 快捷键

Ctrl+S 保存，Ctrl+Enter 运行，Shift+F5 请求取消。画布焦点下 Delete 删除、Ctrl+D 复制、Ctrl+Z 撤销、Ctrl+Shift+Z 重做、Home 适应画布、加号或减号缩放。Ctrl+B 切换左栏、Ctrl+Alt+B 切换检查器、Ctrl+J 切换底部面板。文本框内编辑时画布删除和复制快捷键不生效。

## 0.1.3 本地 AI 文本任务提取

从 PowerShell 启动本轮工作台：

```powershell
Set-Location D:\AIOrchestrationStudio
& '.\dist\AOS-Demo-v0.1.3-win-x64\AOS.exe'
```

在「连接」选择已运行的 Ollama 或 LM Studio，填写该服务显示的回环地址并追加 /v1，点击「测试连接并获取模型」，选中已安装模型后点「保存连接」。默认 Ollama 为 http://127.0.0.1:11434/v1，LM Studio 为 http://127.0.0.1:1234/v1。在 PowerShell 可用 `Invoke-RestMethod http://127.0.0.1:11434/v1/models` 检查 Ollama，将端口改为 1234 可检查 LM Studio。连接被拒绝时先启动其中一个服务；列表为空时选择或加载已有模型。不同版本工作台有独立用户目录，请在本版配置一次。

在「工作流」选择刚配置的提取模型，点「打开任务提取工作流」。选中文本输入，填写会议记录，点击运行。文本处理节点补充提取要求，本地模型返回文本后通过 JSON Schema 验证，必须包含 tasks 数组，每项包含 task、owner、due。未知负责人和期限使用 null。模型输出多余说明、无效 JSON 或缺字段时流程会失败。审批面板可核对完整任务内容并批准或拒绝。需要修正时请拒绝，调整输入后重新运行。

批准并完成后，在工作流侧栏填写结果文件名并点击「保存已检查结果」。界面显示的目标是本版用户工作区 workspace/results/名称.json。重名会拒绝覆盖。「重新打开结果」按输入名称读取。运行详情中的耗时从创建工作流至最近一次节点派发或完成，可能包括人工等待。它不能直接用作纯推理耗时。

本次两个预设服务均拒绝连接，真实推理请求为 0。直接调用与 AOS 的模型、Token、推理耗时、合格率及可比较的总耗时均待测。真实窗口独立验证了非法 JSON、错误字段、手工合法 JSON 的批准和保存重开。证据见 demo/extraction/qa-1794063090024/evidence.json。下一项优先工作是用一个已加载的本地模型跑完此示例，核对输出质量及首次加载是否超过现有超时。

## Gemma 首次实机验证（2026-11-08）

启动现有 `dist/AOS-Demo-v0.1.3-win-x64/AOS.exe`。本机已将项目 `demo/local_models.py` 修复同步至 `%LOCALAPPDATA%/AOS-Demo/v0.1.3/experiments/p0-08/local_models.py`。原 ZIP 未更新，重新解压到全新机器后须先启动一次并关闭工作台，再将该源码文件复制到上述位置。

在「连接」选择 LM Studio，测试 `http://127.0.0.1:1234/v1`，选中 `google/gemma-4-e4b` 并保存。「打开」中选择本机已保存的 `gemma-text-96713877`，点击运行。也可导入项目 `demo/extraction/gemma-verification/gemma-text.document.json`。任务提取请在工作流侧栏切换为 LM Studio，再打开提取模板。会议时间与任务期限分别核对，现有 Schema 的字段为 due。

模型已加载。首次无认证自我介绍请求返回 200，但 128 个输出 Token 耗尽，正文为空。相同上限使用 reasoning_effort=none 后得到正文（18 输入、33 输出、472 ms）。适配器仅对该 LM Studio 模型应用此参数，并识别空正文。原 SDK 的占位凭据也能列出模型；本次未复现历史 401。修复使用 SDK 每请求显式省略 Authorization；将 omit 仅放入客户端默认头会触发 SDK 本地校验错误。

相同编排说明输入、单条 user 消息、128 Token 上限的热模型基线：直接 API 30/109 Token、4770 ms；首次窗口 30/78、C1 872 ms；保存重开后 30/66、C1 1077 ms。后一次服务端报告首 Token 112 ms、推理 650 ms；C1 模型节点 929 ms。同次总耗时与服务推理相差约 427 ms，包含 SDK、连接、每次执行前的列表检查、数据传递及调度，不能全部归于调度。首次窗口返回的文本含格式符共 127 字符，模型未严格满足 100 字限制。不同输出长度不可直接用于比较速度。此次三次直接推理、三次窗口推理；每次工作流模型节点一个 attempt，审批恢复未再生成。任务提取返回两项分工，due 均为 null，通过现有 Schema。
