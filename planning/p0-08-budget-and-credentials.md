# P0-08 预算、凭据与真实 API 准备

## 可信边界

Windows Credential Manager通过已存在的 pywin32 312 调用，不自行加密。只使用 `AOS/P0-08/Synthetic/fixture-<运行目录摘要>` 下**本轮创建**的假凭据，不枚举凭据、不扫描环境变量或用户目录、不使用 Codex/ChatGPT 账户密钥。工作流仅含 `credential:fixture`；环境绑定再经 E3 解析到本机凭据。用户输入不能指定任意凭据目标。

SDK异常正文、响应头及密钥不序列化到状态/日志；只返回固定错误码。模型输出若含本次假密钥或测试敏感前缀则拒绝。HTTP账本只保存 authorizationPresent布尔值，不保存认证头。这是当前凭据路径的脱敏检查，不是通用数据防泄漏系统。

正常关闭删除本轮目标；强制终止会留下会话级合成凭据。收据只含明确别名；应用都停止后，`cleanup_credentials.py`仅删除收据对应目标。恢复可重建同一合成目标，**不等于恢复/轮换真实用户凭据的授权**。第二控制器在任何清单/凭据操作之前先申请运行库锁，不能影响第一控制器。

## 原子准入与结算

唯一权威仍为 C1/SQLite。无独立预算服务或第二账本。`node-dispatched`事务同时写 attempt、Token预留和费用预留，串行执行器控制循环在同一事件循环内完成准入；并发执行的节点不能同时抢占同一余额。原 ControllerLock与事务序号检查继续防双写。

- 单次 Token预留 = maxInputTokens + maxOutputTokens；输入准入采用 **UTF-8字节数+128的合成上界规则**，不冒充任意供应商 tokenizer。
- 单次费用预留 = maxCallCostMinor；同时检查节点预算、运行预算、币种和当前确认/预留余额。合成费率为每100 Token向上取整1分，准入还检查预留是否覆盖该合成上界。
- 并发受原运行/节点 concurrencyLimit约束。预算不足时在派发前失败；不自动提高上限。失败依赖不会继续。
- `node-terminal`同一事务结算已返回输入/输出 Token；usage缺失保留完整预留，即使输出合法且节点成功。
- 超时、丢响应、取消、崩溃无结果时保持unknown及预留；不重发、不自动解冻。收到明确4xx会业务失败，但未返回可信用量时仍保留费用不确定性。
- SDK自动重试为0，模型节点禁止不安全多attempt；请求身份和前端重复动作还受既有 IPC receipt/C1控制。

`usage.spentTokens/reservedTokens`包括模型实际确认/预留 Token；attempt.modelUsage保留输入输出分项或null。**`usage.costMinor`是旧合成内核的零费用字段，不是实际账单**；新模型费用只在同一权威快照的 `modelCosts` 中，带 pricing/currency/invoiceVerified=false。GUI只显示“合成估算/预留”，不将两种字段相加或声称真实扣费。后续正式运行状态契约应统一这两个有不同含义的费用字段再开放通用客户端。

T18通过真实 SDK返回输入900/输出100/总1000，而 maxOutputTokens=128，证明原反例已被正确区分。T09并发抢占和T19缺失usage后的串行再准入均有实际 HTTP次数断言。

已准备两条 SDK调用路径、错误/取消映射、结构化输出和同组测试框架。**当前可选择的配置仅为固定离线夹具**；实际 OpenAI/Anthropic 模型未配置、不可派发。开放真实调用前仍需补充受检模型配置数据及专属计量/费率，不能把离线名称替换成任意字符串就运行。

1. 用户明确供应商、具体模型/API版本、凭据用途、总预算及调用次数/范围。
2. 为该明确模型核实采样/输出/结构化能力、输入计量与价格；新增版本化能力数据与受限环境绑定，保留当前离线回归。
