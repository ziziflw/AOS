# Reuse First — 成熟技术优先复用开发原则

生效：2026-10-29。状态：**用户已明确采用的项目开发原则**；具体组件和最终技术栈仍需验证，不因本原则冻结。适用于AOS后续核心功能开发、依赖升级与基础设施替换。项目根[AGENTS.md](../AGENTS.md)提供后续任务的执行入口。

## 1. 决策顺序与适用范围

**已有依赖/已有代码 > 成熟SDK或组件 > 独立服务 > 合法复用部分源码 > 自研。**

先确认所需能力是否已经存在，再审查维护正常且可满足要求的成熟方案。能调用API或薄适配解决的，不复制整库、不fork；能复用协议SDK的，不重写完整协议栈。该顺序是优先审查顺序，不是无视需求、安全和总成本强制安装的排名。

重点覆盖：图编辑基础设施、供应商协议、MCP/A2A、持久化恢复/调度、追踪、凭据和多模态执行等长期架构能力。字段映射、节点能力投影、边界校验、业务命令绑定和小型UI胶水可直接实现；一旦胶水开始承担协议解析、通用表单框架或恢复引擎，应重新触发复用评估。

不因依赖更少就重造复杂设施，也不为减少几行代码引入网关、数据库服务、Agent平台和管理后台。依据：**总工程成本 = 初期集成 + 长期维护 + 兼容/安全成本**；有数字就附测量环境，未测量只给定性判断和测量计划，不虚构性能、体积或工期。

## 2. 每次核心开发前的最小评估

在[组件评估](./component-reuse-assessment.md)追加/更新相关条目即可，不必新建重复报告。至少回答：

1. 具体需求、非目标和必须保持的契约是什么？现有哪个模块/依赖可以完成多少？
2. 成熟候选的真实上游、维护状态、精确版本/提交、API与许可证是什么？
3. 是否能直接依赖、使用现有API或独立服务？薄适配为何不足、何时才必须fork/复制？
4. 直接和传递依赖、原生二进制、生命周期脚本、网络/遥测/自动下载与安全公告如何？
5. 对Windows打包、未来Linux/macOS、凭据边界、取消/重试/恢复和升级维护的总成本如何？
6. 推荐继续复用、隔离试验、暂缓还是自研？替换风险、验证门槛和回滚是什么？

每条结论标记证据层级：**L=本项目已有实际证据**（注明历史日期/版本）、**R=本次源码/锁文件/上游文档或元数据审查**、**P=待实验的建议**、**U=未核实/未验证**。文档宣称支持不能标成L；历史通过不能当作本轮复测；候选已下载许可证不等于安装或安全批准。

## 3. 准入条件

采用前须满足许可证、可信来源、行为可控、依赖可部署、状态权威兼容五项门槛；任何一项不满足，不以综合评分掩盖。维护评估看发布/提交、修复和弃用政策、已知公告与源码可得性；星数和下载量只是背景，不是安全或质量证据。

固定发布版本/源码SHA及制品哈希。默认分支SHA用于审查定位，不能冒充某个已发布wheel/npm制品的来源证明。采用时建立 **发布tag/commit → 制品及SHA256/integrity → 完整锁定依赖 → 本地构建身份** 的记录。不能使用浮动latest或仅凭旧“干净版本”公告认定安全。

审查被实际启用的extras/功能：SDK与Proxy、OSS与enterprise、API与SDK/exporter分别计算，不只看顶层包。用隔离新环境做解析/构建/试验，不升级旧P0实验环境；禁止自动执行未审查的远程脚本、install hook、`.pth`或动态下载。对无匹配wheel/原生扩展的平台明确报告，不通过关闭证书验证、提权或删检查过关。

安全公告检查有日期/链接和适用版本；未知风险标U，不能宣称“零漏洞”。本次查到LiteLLM的实际发布链事件，处置见组件评估；原则同样适用于所有SDK，不把成熟或官方等同绝对可信。

## 4. AOS与第三方的职责

| 成熟组件直接负责 | AOS必要适配/控制 |
| --- | --- |
| Vue Flow视口、拖拽、选择、端口、连线交互 | 原工作流定义与独立布局映射、业务端口兼容、不可变运行投影 |
| 模型SDK的HTTP、认证字段、协议对象、响应/流解析、供应商异常 | 经核验的模型能力Schema、secretRef受控解析、D1结果/usage映射、C1准入/预算/状态 |
| 官方MCP/A2A SDK的协议与传输 | 工具/Agent白名单、身份/版本绑定、C1门禁、未知副作用与原taskId核实 |
| 成熟存储/可能的执行框架原语 | 原契约映射与唯一权威设计；不得同时保留两个自主业务状态机 |
| OpenTelemetry API/SDK/exporter的追踪标准 | run/node/attempt关联、脱敏、保留策略；trace不作为恢复或终态权威 |
| ComfyUI官方服务API及其内部执行 | 受控任务提交/查询、产物类型/来源、资源/任务身份和取消范围 |

SDK可能自带retry、fallback、router、缓存、Agent循环或自动工具执行。本项目默认关闭自动业务重试/fallback/工具执行，或将其明确纳入C1批准的同一attempt预算；严禁出现C1、SDK、网关三层各自重发。客户端取消/超时不能证明远端没执行或没计费。未知usage不能写成0，不能将billable改成none来绕过既有保护。

## 5. 合法源码复用与升级

允许在许可证与安全要求满足时直接引入依赖或具体模块，无需为“自主开发”重写。优先官方包/API；仅当发布包不能满足、上游可审查且部分复用的总成本更合理时vendoring。

引入时保留适用LICENSE、版权及NOTICE，明确目录/文件属于第三方还是AOS、精确来源、上游SHA、本地修改及原因。不得把复制来的源码重新标为AOS原创。以独立patch/变更清单记录修改，记录同步上游、回归、负责人/维护归属和移除/回滚方法；禁止默默维护无法升级的整库fork。

MIT/Apache等标签不能代替逐包逐目录核验；enterprise、模型权重、插件、图片和商标可能另有条款。GPL类源码复制/链接及二进制再分发须单独审查适用义务；接独立服务也不自动豁免该服务的分发义务。尚无授权依据就不复制限制性代码，不把“可访问GitHub”当作许可。

本轮只归档候选公开许可证和元数据作研究，**没有引入候选运行源码/依赖**。已安装组件仍以旧实验的lock、许可清单和实际制品为准。

## 6. 重大替换与单一状态权威

C1仍是本地workflow run、node、attempt、iteration、approval和业务终态的唯一权威。Rust、Vue、SDK回调、遥测后端和远端Agent/ComfyUI任务事实都不能直接覆盖C1库。

替换C1/存储、引入框架checkpoint或改变权限边界前，先提交最小反例、独立对照实验、差异表和迁移/回滚方案，再由用户确认实施。对照实验可独立开展已授权部分；不能以“成熟框架”绕过该门槛，也不能把本轮文档任务扩成替换任务。

若候选最终作为引擎权威，C1旧业务写入器必须停止并退为接口/只读投影；若候选仅管理独立Agent内部任务，须明确命名空间与外层run的事实转换。禁止同一run由两套checkpoint/snapshot各自决定终态。影子对照使用各自独立合成账本，不让两个引擎真实派发同一外部操作。

迁移至少定义固定workflow/node版本、旧run读写/恢复兼容、在途unknown/审批/taskId、事件顺序、数据备份和停用新执行器后的回滚。未解决不能扩大集成；保留C1及P0-03至P0-07作为合同/故障语义回归基线。

## 7. P0-08开发准入与当前停止点

下一轮先实际比较成熟SDK；本轮只制定计划，不安装候选、不实现模型适配或改UI。比较在隔离目录用可信本地HTTP服务，两种代表性供应商协议，同一组输入与断言；SDK承担HTTP及协议，AOS测试服务只提供合成响应/故障。

必须测unsupported参数、结构化输出/错Schema、usage有无、429/错误、超时/取消/丢响应、自动重试次数、并发预算、凭据脱敏和C1闭环。能力与预算不满足时先给最小扩展决策；实际SDK/本地HTTP通过、真实供应商通过、真实计费确认分别记录。具体方案见[评估第5节](./component-reuse-assessment.md#5-p0-08实际sdk对照门槛尚未执行)。

重大替换依本政策确认，普通适配在用户已授权任务内自主完成，不反复请求许可。收费实验另需供应商、具体模型、凭据用途、预算及调用范围的明确授权；未授权则完成其他可执行离线工作，停止于收费请求之前。

```text
总成本与Windows/跨平台风险（未测项写明）：

```

本轮不改旧实验、不调用模型、不修改PFT、不提交Git；更新政策评估不等同冻结技术栈。
