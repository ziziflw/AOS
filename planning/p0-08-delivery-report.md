## 最终问题回答

| 问题 | 实际结论 |
|---|---|
| 1 成熟SDK是否复用成功 | 是。由官方SDK直接发送HTTP、解析对象与供应商错误，AOS不自写协议客户端 |
| 2 哪些版本实测 | openai3.41.0、anthropic2.3.0、httpx2/httpcore2 2.16.0；Python3.12.14，完整依赖哈希固定。LiteLLM/Vercel SDK本轮未运行 |
| 3 原C1是否运行模型节点 | 是。Text输入→model-kind节点→Text输出；JSON变体经类型明确的提取器；原调度/SQLite/attempt唯一权威 |
| 4 参数差异如何处理 | 每协议/输出能力独立NodeDefinition configSchema和Adapter parameterSchema；UI动态显示、后端拒绝未知参数。只证明固定离线模型，不泛化所有真实型号 |
| 5 VueFlow是否实际联动 | 是。真实Tauri窗口添加/配置/保存/运行与状态/输出/usage联动，有截图、交互记录和独立SQLite对照 |
| 6 凭据是否可信存储引用 | 自有合成凭据已通过Windows Credential Manager验证，只保存别名。未扫描或使用真实密钥；真实用户凭据配置GUI尚未实现 |
| 7 预算/并发是否生效 | 是，在合成计量/费率范围。派发原子预留、并发1/2、并行争用、缺usage阻止后续调用均有HTTP次数和状态断言 |
| 8 Token/费用/取消可信边界 | Token来自自有服务经SDK返回；缺失null并保留额度。费用仅合成估算、非账单；取消/超时/断连不能承诺远端停止或不计费 |
| 9 MCP/A2A/宿主是否正常 | 原专项全部回归通过；新宿主另外真实运行MCP审批。未改MCP/A2A实现，未新增A2A管理GUI |
| 10 哪些是真供应商证据 | **没有**。本轮有真实SDK、HTTP、Tauri与系统凭据API；响应/用量/费用仍为自有合成服务数据 |
| 11 新供应商如何增加 | 通过官方SDK薄映射、版本化能力/环境绑定及同组测试；无需另建调度器。不同协议仍需实际验证 |
| 12 距正式自用还缺什么 | 受授权的具体模型与凭据配置、真实计量/费率和少量API实测、费用状态契约统一、未知消耗核实入口、发行依赖闭包与干净Windows机器验证 |

## 保持的边界

PFT未接触；旧研究/实验/失败证据保留。P0-03只抽取默认行为不变的usage校验钩子，原MCP/A2A与P0-07源码不改。宿主不能自行宣布业务终态；审批仍由C1强制，派发边界二次检查身份/有效批准。没有通用脚本、任意命令、任意URL或真实账户入口。

SDK候选及闭包在独立venv中审查/锁定；未安装受污染LiteLLM、未下载模型、未自动提权、未Git提交/标签/推送。Windows Job与凭据API不是完整OS沙箱。

## 下一步与停止点

优先为用户选择的**一个明确供应商/模型**补齐能力、计量、费率和授权配置后，做极少量真实文本/JSON调用；保持当前UI，暂不扩展复杂多模态或更换C1。授权必须明确凭据用途、总预算和次数/范围。供应商取消/计费必须另核实，不能把本轮模拟费用变成收费保证。

完成本轮后停止，不自动进入P0-09，不冻结最终技术栈，不宣称正式产品可发布。
