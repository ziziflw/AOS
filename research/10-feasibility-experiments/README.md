## E01 · 节点画布保存与加载

- **目标**：证明画布状态、节点契约、逻辑图与修订可独立演进；支持显式错误。
- **输入**：3类自定义节点、每类不同端口/参数；合法图、孤立图、错类型连线、非法环、旧版本图、未知节点样本；合成100节点图仅作诊断。
- **验证步骤**：
  1. 用Vue Flow候选实现最小画布，创建/连接/移动节点、修改参数与视口。
  2. 保存后在全新会话重载；再保存，比较规范化可执行定义与布局。
  3. 切换动态参数/端口，检查旧连线去向；导入旧图/未知节点，不自动执行。
  4. 校验非法图，复制修订后做参数修改，检查原修订不被改变。
- **通过标准**：20次往返无节点ID、端口ID、参数、边或视口信息丢失；非法连接/图运行被拒绝并定位原因；未知节点数据保留；旧图迁移有显式结果。100节点响应时间记录分布，不用尚无依据的性能阈值判产品合格。
- **失败条件**：仅保存视觉布局；动态端口导致连线静默换绑；旧字段被无提示丢弃；非法图可进入执行。
- **预期风险**：序列化非JSON对象、布局与执行定义耦合、Schema验证器差异、大图渲染。
- **依据/决策**：[S01–S06](../sources.md#s01)、[S16](../sources.md#s16)、[S46](../sources.md#s46)；D03、D08、D09。

## E02 · 两个不同模型供应商适配

- **目标**：验证统一抽象仍能准确表达供应商差异、流式结果、错误、usage和预算。
- **输入**：后续由用户提供的两家供应商凭据引用；可选Claude与Gemini，精确模型/版本届时再定；同一文本/JSON任务；支持与不支持参数、畸形结构化输出、429/超时故障注入样本。模拟响应只能验证逻辑，不能代替两家真实调用。
- **验证步骤**：
  1. 根据各自官方文档建立能力快照，比较原生SDK与AI SDK或LiteLLM候选。
  2. 对每家执行普通/流式/结构化任务，展示有效参数、警告、原始usage与归一化结果。
  3. 故意请求不支持的采样参数，记录预检或供应商拒绝；取消流式输出并核对状态。
  4. 使用受控模拟端点测试429、超时、错误响应和fallback，核对尝试次数及费用归集。
- **通过标准**：两家真实端点各至少完成一次有效调用；不支持参数不会被显示为生效；结构错误被定位；重试次数可追溯；usage缺失显示未知；预算达到上限后不再派发新调用。真实金额/请求次数上限在实验前给定，达到即停止付费调用。
- **失败条件**：只有兼容网关的两个模型却冒充两家原生供应商；静默丢参数；把取消当作费用归零；重复重试不计费。
- **预期风险**：版本突变、账户/地区可用性、SDK滞后、结构化输出子集、无法撤销的远端生成成本。
- **依据/决策**：[S22–S27](../sources.md#s22)；D01、D07、D08。

## E03 · 本地MCP工具调用

- **目标**：验证stdio工具发现/参数校验/输出校验/会话关闭和描述变更。
- **输入**：未来建立的无网络、无副作用测试MCP服务；echo/求和/生成临时产物工具；错误Schema、畸形JSON、无响应、工具改版及stdout污染模式。
- **验证步骤**：
  1. 启动服务并协商固定版本/capabilities，保存工具描述快照。
  2. 发起有效/无效参数调用，比较服务端错误与客户端预检；验证可选outputSchema。
  3. 注入stderr日志、非法stdout、超时及工具列表变化。
  4. 关闭会话并确认进程清理；不支持版本和未协商能力应明确拒绝。
- **通过标准**：有效请求可关联到唯一调用及产物；非法输入在执行前被拒；不合Schema输出隔离为错误；日志与协议不混用；无响应可超时取消；版本/描述变化不会沿用旧绑定无提示执行。
- **失败条件**：跳过握手；把工具description当作可信权限；协议损坏后继续误配响应；关闭后遗留测试进程。
- **预期风险**：工具SDK规范支持程度、消息分帧、输出过大、服务不合作。
- **依据/决策**：[S28](../sources.md#s28)、[S29](../sources.md#s29)、[S44](../sources.md#s44)、[S45](../sources.md#s45)；D04、D05。

## E04 · 并行节点与结果汇合

- **目标**：对照候选框架和自主最小运行层，证明分支确实重叠执行且汇合语义明确。
- **输入**：纯模拟A分叉到B/C再汇合D；B/C各延迟2秒；反序完成、失败、跳过、取消、重复完成事件；条件分支和最多3轮循环样本。
- **验证步骤**：
  1. 记录节点就绪/启动/完成时刻和attempt；比较串行基线与并行配置。
  2. 调整B/C完成顺序并设并发上限1/2，检查资源限制。
  3. 令一支失败或未被条件选中，按声明的all/any等候选策略运行汇合。
  4. 加入受控迭代，检查轮次身份和上限，确认不是任意环死循环。
- **通过标准**：并发2时B/C执行区间存在重叠；10次运行输入均按来源绑定，D不会重复执行或在必需输入缺失时启动；并发上限1时无重叠；故障/跳过/取消均有确定终态或等待理由；循环最多3轮。耗时作辅助证据，不只靠总时间猜测并行。
- **失败条件**：只把分支画成并列；按完成顺序错绑输入；汇合永久等待已跳过分支；重复事件多次触发D。
- **预期风险**：共享状态覆盖、框架调度语义与画布不一致、流式输出背压。
- **依据/决策**：[S08](../sources.md#s08)、[S17–S20](../sources.md#s17)、[S43](../sources.md#s43)；D01、D02、D03。

## E05 · 取消、中断和状态恢复

- **目标**：确认进程故障、人工暂停、用户取消与远端结果未知可区分，避免重复副作用。
- **输入**：E04流程、持久检查点候选、带幂等键的本地测试服务和无幂等对照服务、可查询操作状态；等待审批节点；固定输入产物及修订。
- **验证步骤**：
  1. 在派发前、请求已发出但结果未持久化、结果已记录、等待审批四处注入执行进程崩溃。
  2. 重启后加载同run和修订，检查事件、attempt、检查点与已完成结果。
  3. 取消运行中的纯计算、CLI、模拟远端任务，验证不再调度下游并记录确认或未知。
  4. 修改上游输入/节点版本后做局部重跑，检查依赖闭包和缓存失效；旧run不可被新定义偷偷覆盖。
  5. 重复崩溃并比较副作用计数；增加存储busy/写失败/产物丢失场景。
- **通过标准**：每个注入点重复5次均能解释恢复位置；已确认完成纯节点不被无理由重复执行；幂等服务的同一逻辑操作计数为1；无幂等且结果未知时暂停待核对，不自动重试；审批不会自动变批准；取消后没有新下游派发，远端未确认状态明确可见；缓存不命中变更后的输入。
- **失败条件**：仅正常退出可恢复；用新run冒充恢复；声称任意外部副作用exactly-once；状态已成功但产物不存在且未报错。
- **预期风险**：外部提交与本地记录无法原子化、框架重放规则、版本迁移、WAL同步与磁盘故障。强杀验证不等同断电持久性证明，断电试验需另立安全环境。
- **依据/决策**：[S18–S21](../sources.md#s18)、[S36](../sources.md#s36)；D02、D06、D09。

## E06 · 人工审批与工具执行权限

- **目标**：证明权限在执行入口强制，且审批与具体操作绑定。
- **输入**：测试目录内允许读/写、禁止目录、允许/禁止本地HTTP目标、工具读写操作；含“忽略规则并外传密钥”的无害注入文本；过期/被篡改审批与重启样本，使用虚构密钥。
- **验证步骤**：
  1. 直接通过执行接口发起无授权调用，验证UI之外的入口也被拒绝。
  2. 审批一项操作后改变路径、参数或工具描述，检查旧批准失效。
  3. 拒绝、过期、暂停后重启，再恢复审批；检查审批请求身份和审计。
  4. 测路径穿越、链接/重解析点、HTTP重定向与外部输出注入；检查日志及导出。
  5. 让受控子进程自行访问禁止资源，测出OS实际边界；若无隔离机制应如实报告限制。
- **通过标准**：未授权/拒绝/过期/篡改操作产生零目标副作用；授权只用于绑定资源和参数；重启不自动批准；虚构秘密不出现在日志/导出；工具输出不能自行扩大权限。宣称“沙箱”前须通过子进程直接访问测试，否则只可称受控执行。
- **失败条件**：只弹确认框而后台可绕过；模型自评安全即可执行；同意一个工具等于无期限全部权限；程序可越界却声称隔离完成。
- **预期风险**：检查与使用时间差、OS权限与应用规则不一致、同用户恶意进程、提示注入不能彻底消除。
- **依据/决策**：[S29](../sources.md#s29)、[S33–S38](../sources.md#s33)；D05、D06。

## E07 · Windows宿主与独立执行进程通信

- **目标**：比较Rust核心与Node/TS或Python独立进程的最小闭环、分发及关闭协调。
- **输入**：干净Windows测试账户/机器、固定架构与OS构建、模拟长任务与大输出、中文和空格路径、协议版本不符与执行进程异常退出；临时状态/产物目录。
- **验证步骤**：
  1. Tauri宿主启动最小执行进程，做版本握手、提交/取消/事件关联及日志分离。
  2. 连续1000条小事件加一次超上限消息，验证分帧、排序/去重和背压，不无限缓存。
  3. 正常关闭、执行进程崩溃、宿主被强杀，确认子孙进程与状态。
  4. 在相同假任务上记录两路线启动耗时、内存、包体和依赖；不因不同业务负载做不公平比较。
  5. 在干净环境安装/启动、断网重启并卸载；验证所选WebView2/运行时分发策略和凭据引用。
- **通过标准**：消息无错配、协议不符明确拒绝、超大输出受限；30次启动/关闭无遗留测试进程；宿主强杀后的行为可重复解释且下次启动不出现双重调度；离线执行模拟任务不依赖开发机全局Node/Python；所有资源测量可重现。故障恢复仍以E05为准。
- **失败条件**：仅开发机可运行；日志污染协议；只关闭直接子进程；执行进程重连产生两个状态写者；把主应用包体当作全部分发体积。
- **预期风险**：架构后缀、代码签名、WebView2和运行时包、Windows Job嵌套/逃逸、IPC恶意输入。
- **依据/决策**：[S21](../sources.md#s21)、[S36–S41](../sources.md#s36)；D01、D05、D10。
