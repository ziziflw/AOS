# R06 · 可观测性、成本与质量评估

[OpenTelemetry](../sources.md#s31)提供Trace/Span、事件及因果链接；[Langfuse](../sources.md#s32)提供追踪、成本延迟、prompt版本和评估工作台。两者是参考/复用候选，本轮没有部署。

## 候选事件与责任

运行控制模块拥有业务状态；基础设施提供存储；观察模块只消费事件构建视图，不反向决定运行状态。遥测采样、后端丢包或不可用不能破坏恢复记录。

建议关联workflow修订、run、节点实例、attempt、adapter请求、审批、产物与trace。并行汇合或跨run局部重跑可以用Span Links表达因果。不要将OTel Span状态直接当作本项目完整运行状态机。

输入输出记录采用分级策略：默认摘要/Schema/产物引用；经允许才记录正文，二进制另存；敏感字段脱敏发生在持久化和导出之前。错误信息、HTTP头、工具stderr与prompt也可能泄密。

## Token和费用口径（初步设想）

| 数据 | 口径 |
| --- | --- |
| usage | 保存供应商原始计数类别及归一化结果，保留缺失/未知 |
| 成本 | 标记实际账单、依据usage计算、估算三类，不混为一列 |
| 价格快照 | 供应商、模型、API/服务层、时间、币种、计价单位 |
| 重试/fallback | 每次请求单独记录，并汇总至节点attempt与run |
| 预算 | 调度前预留，完成后核对；中断时未结算费用保持未知 |

不能从统一SDK推断所有供应商相同token口径；本轮不报模型价格，不承诺取消后不计费。

## 可复现评估设计（待验证）

固定数据集版本、输入摘要、节点/工作流修订、模型标识、API版本、参数、prompt版本、缓存政策和评分器。多次重复运行同时保留质量、延迟、首token、失败率、token、成本及未知费用比例。随机性和供应商变更限制严格复现。

先对可确定任务用Schema/断言/参考答案评分；开放生成可用盲评及明确量表。LLM-as-judge只能作辅助，需校准、记录评分模型与偏差，并计入成本。不要将单次漂亮输出当作基准成绩。

多模型比较应使用同一输入与预算口径，同时公开不支持参数及有效参数；不得让某模型静默丢弃选项后仍称同参数对照。结果表能追溯失败与样本缺失，不只展示成功run。

E02记录usage与错误；E04关联并行支路；E05确保恢复不会产生重复计数；E07验证跨进程trace与离线导出。大规模基准和评估平台选型留到后续。
