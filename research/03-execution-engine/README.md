## 已核实的能力与容易混淆处

- [LangGraph](../sources.md#s17)面向有状态长任务；[checkpointer与store](../sources.md#s18)用途不同。内存checkpointer示例不是磁盘恢复方案。
- [Interrupts](../sources.md#s19)允许暂停与恢复，但节点会重新执行，暂停前副作用需幂等。恢复不等于从任意代码指令位置继续。
- [Temporal](../sources.md#s20)以事件历史与重放恢复Workflow，依赖Service和Worker；确定性约束是接入成本的一部分。
- [SQLite WAL](../sources.md#s21)解决部分本地事务与读写并发问题，同一时刻仍单写者；它不定义节点调度与外部副作用。
- [ComfyUI缓存](../sources.md#s05)体现输入变化与外部资源指纹的重要性；[Node-RED Context](../sources.md#s13)的存储不等于运行日志；[Flowise](../sources.md#s43)已描述checkpoint和人工介入。

## 执行语义候选（初步设想）

| 能力 | 必须先讲清的语义 | 实验 |
| --- | --- | --- |
| DAG调度 | 就绪条件、依赖失败与未选分支的区别、队列公平性 | E04 |
| 并行与汇合 | all/any或显式策略；输入按节点身份关联，不按到达顺序；跳过/失败/取消均有规则 | E04 |
| 条件与有界循环 | 表达式权限、最大迭代/耗时/成本；每轮有独立实例身份 | E04 |
| 持久化恢复 | 固定工作流修订、输入引用、检查点、运行事件；谁是权威写者 | E05 |
| 重试 | 可重试错误分类、节点attempt、退避、总预算；避免SDK和调度层重试相乘 | E02/E05 |
| 暂停审批 | 审批关联操作和参数摘要；重启后仍可匹配；修改参数令旧审批失效 | E06 |
| 取消 | 停止调度、请求适配器取消、确认或标记未知；不能伪造远端已停止 | E05/E07 |
| 局部重跑 | 依赖闭包、历史输入可用性、缓存策略、是否创建新run | E01/E05 |

## 幂等性与外部副作用

若服务端已执行写入、客户端未收到响应便崩溃，恢复后再次请求可能重复。仅有本地事务或checkpoint无法与任意外部HTTP操作构成共同原子提交。**初步设想**：每次逻辑操作携带稳定幂等键，记录“已计划/已发出/已确认/结果未知”；无幂等或查询能力的操作在不确定时要求人工核对，禁止自动宣称exactly-once。补偿动作自身也可能失败，需单独审计。

缓存键候选包含节点实现版本、规范化参数、输入摘要、模型标识/API版本及外部资源指纹。默认仅对明确无副作用且策略允许的节点缓存；模型调用即使temperature为0也不能当作跨环境完全确定。

## 是否自写完整引擎

| 路线 | 可复用部分 | 本项目仍负责 | 风险与当前判断 |
| --- | --- | --- | --- |
| LangGraph作为运行时 | checkpoint、暂停、状态图相关机制 | 图定义转换、权限、文件产物、供应商能力、UI与Windows宿主 | 优先对照候选；本轮未验证任意画布映射和分发 |
| Temporal作为运行时 | 事件历史、重放、Worker模型 | 动态工作流映射、活动幂等、宿主及本地运维 | 作为可靠性参照；不能预先认定本地部署过重或一定合适 |
| 自主最小执行层 | 更易贴合自定节点契约与单机模式 | 调度、恢复、并发、幂等、迁移全部由自己承担 | 仅在成熟框架存在实测阻碍时考虑；范围限制为验证子集 |
| 组合框架与自有基础层 | 框架管运行控制，本地层管策略/产物/宿主 | 协议边界、单一状态权威与故障协调 | 可研究，避免两个调度器同时管理同一run |

当前建议：**不直接承诺自写完整引擎**。E04/E05用同一故障样例比较候选；选定前锁包版本、检查许可，测离线启动、恢复正确性与分发依赖。Rust/TS/Python的语言选择与框架选择有关，但不是同一个决策。
