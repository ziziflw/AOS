# R04 · 模型接入与参数能力

[资料索引](../sources.md) S22–S27；本轮没有调用付费模型，也未安装推理服务。

## 已核实与当前限制

[Vercel AI SDK](../sources.md#s22)提供通用调用选项，但明确供应商可能不支持某些选项并返回warnings；[LiteLLM](../sources.md#s24)提供按模型/供应商查询支持参数的函数。统一SDK减少适配工作，不会消除底层差异。

[Claude API版本页](../sources.md#s27)明确2026-10-21版本删除temperature、top_p、top_k。旧SDK示例或旧API参数表仍可能出现这些字段，因此能力标识至少包含供应商、模型、接口类型、API版本和适配器版本。这是已核实的版本差异，不是文档冲突下强行选择一方。

[vLLM](../sources.md#s25)的兼容接口并不逐参数相同；例如Chat依赖模板，部分参数不支持或被忽略。**待验证**：其原生Windows部署及本机硬件可行性。本项目可连接已有本地/局域网服务，不必把推理服务捆绑入桌面应用。

[Gemini模型目录](../sources.md#s26)可用于发现候选模型，但不能从模型列表推导所有参数范围、结构化输出子集、限额或账户可用性。

## 接入路线对照

| 路线 | 适用理由 | 必须测量 |
| --- | --- | --- |
| AI SDK直连 | 候选TS执行进程，统一文本/流式调用并保留provider选项 | warnings可见性、取消、usage、结构化输出能力 |
| LiteLLM SDK/Proxy | 候选Python执行进程或需要路由的网关 | SDK最小依赖、Proxy额外服务、重试与限流责任 |
| 供应商原生SDK/HTTP | 新能力尚未被统一层覆盖时可直接接入 | 自行承担流解析、错误归类、版本与计费映射 |
| 已有本地HTTP端点 | 保持推理和编排分离，避免模型安装进入桌面范围 | 健康检查、鉴权、模型别名及真实能力探测 |

上述是评估建议，尚未选择默认方案。

## 参数与结果的候选抽象

参数描述应区分：支持/不支持/未知、范围和默认行为、互斥条件、供应商原生字段与实验性字段。Temperature、top-p、max tokens、推理预算、工具调用、结构化输出不能同等处理。不支持时在执行前拒绝或明确提示；不得静默删除后仍显示“已生效”。

结果分为文本/结构化内容/工具请求/流事件/usage/结束原因/警告。模型提出工具请求只是建议，真正工具执行仍需经过策略模块；结构化输出需要运行时校验，不能将parse成功当作符合业务类型。

能力发现候选由静态注册、服务端元数据和受控探测组成；记录证据时间与来源。未知能力不能默认支持，探测本身会耗费额度，后续实验须有预算。

## 限流、重试与成本

[LiteLLM Router](../sources.md#s23)已有冷却、fallback、超时和重试设计可借鉴。本项目的调度预算与供应商请求重试须划清：供应商适配处理一次调用内网络重试，执行层决定节点attempt；总尝试数必须可解释。

并发限制候选分为全局run、供应商/模型、工具、资源组四层；预算需在派发前预留，结束后按usage结算。费用记录区分供应商实际usage、估算、未知；重试和fallback计入，不能只记录最终成功调用。价格表需附日期/币种/版本，本轮不固定价格或额度。

E02以两家供应商验证参数拒绝、Schema失败、429、超时、流取消、usage缺失和fallback成本；E04验证并发限制。本轮尚无实际兼容性结果。
